## プロジェクト名
COTABI - カップル旅行記録アプリ

## 1. プロジェクト概要

### 1.1 目的
- Claude Codeの実践練習として、実際のシステム開発プロジェクトの流れ(要件定義 → 仕様策定 → 実装)を体験する
- 副次的な成果物として、恋人と二人だけで使う旅行記録アプリを完成させる

### 1.2 対象ユーザー
- 本人および彼女の2名のみ(クローズドな利用、外部公開なし)
- アカウントはFirebaseコンソールから手動で2件のみ作成する運用。アプリ側に新規登録機能はない

### 1.3 コンセプト
- 旅先で実用的に使えるツールでありつつ、これまでの旅の記録が視覚的に蓄積されていくアプリ
- 世界地図・日本地図上で訪問済みの国/都道府県が色付けされ、タップするとその場所での思い出(記録)を閲覧できる
- ホーム画面はマップをメインとし、「国をタップ→詳細記録を閲覧」という導線を軸にする

### 1.4 コスト方針
- 採用する技術・サービスは**すべて完全永続無料**であること(Claude Codeの利用料金は対象外)
- Apple Developer Program($99/年)への登録が前提となる機能・配布方式は採用しない

### 1.5 アプリ形態・配布方式
- **ネイティブiOSアプリ(SwiftUI/Xcode)ではなく、PWA(Progressive Web App)として開発する**
- 変更理由: 無料のApple Developer Personal Teamでは、証明書・端末登録・インストール用プロファイルが**発行から7日で期限切れ**になる制約があり、Macなし・完全無料での長期運用が事実上困難と判明したため
- PWAであればMac・Xcode・Apple Developer Programが一切不要で、Windows上のブラウザ・エディタだけで開発が完結する
- ホーム画面へのアイコン追加、オフライン表示、位置情報・カメラアクセスなど、必要な機能の大部分はPWAで実現している
- 制約: プッシュ通知やバックグラウンド処理の自由度はネイティブアプリより低い(iOS Safariの制限による)

### 1.6 開発環境・デプロイ運用
- 開発端末はWindows(Mac不要)。コーディングはWindows上のClaude Code / VS Codeで行う
- **デプロイは現状、開発者のWindows端末から手動で行う**(`npm run deploy:hosting`でビルド+Firebase Hostingへのデプロイを実行)。GitHub Actions等によるpush連動の自動デプロイは、コスト方針上は選択肢として残しているが、現時点では未構築
- リポジトリは公開(public)のまま(実データはリポジトリに含めない方針は変更なし)

## 2. 機能要件(全機能・フェーズ別・実装状況)

### Phase 1: コア体験(MVP) — **実装完了**

| 機能 | 内容 |
|---|---|
| 訪問マップ | 世界地図・日本地図で訪問済みの国/都道府県を色分け表示。大陸単位の絞り込みにも対応。タップで地域詳細(ルートマップ)へ遷移 |
| 旅行記録 | スポット単位(位置情報付き)で写真・日記・日付を記録。写真は1スポットにつき複数枚自由に追加可能 |
| 記録タイミング | 現地でのリアルタイム記録、帰宅後の清書きの両方に対応 |
| 記録者の区別 | 誰が記録したデータかを表示 |
| データ共有 | Firebase(Firestore + Authentication、無料枠)による二人限定の共有。片方の記録がもう一方にも同期 |
| 統計表示 | 訪問した国・都道府県の数を表示 |
| アルバムまとめ | 旅行単位(1回の旅行=1アルバム)で写真をまとめて閲覧 |
| 旅程表(レベル1) | スポットに日付を入力し、時系列のタイムラインとして表示 |
| ルート表示(レベル2) | 登録スポットの位置情報を時系列順に直線で結び、地図上に表示(実際の交通経路ではなく直線接続)。旅行の登録順に固定パレットで色分け |
| PWA基本機能 | ホーム画面へのアイコン追加、オフラインでの記録閲覧に対応(Service Worker) |
| 記録・旅行の削除 | スポット単位・旅行単位(含まれる全スポット・全写真をまとめて)での削除に対応。取り消せない操作のため確認ダイアログを必ず挟む |

### Phase 2: 体験向上 — **実装完了**

| 機能 | 内容 |
|---|---|
| プライバシーロック | アプリ起動時・バックグラウンドから一定時間(5分)経過後の復帰時に簡易ロックを挟む。WebAuthn(生体認証)を優先し、未設定/失敗時は4桁PINにフォールバック。Firebase Authenticationのログイン状態とは別レイヤーの「端末上ののぞき見防止」であり、ロック中でもログインセッション自体は維持される |
| 思い出フラッシュバック | 「〇年前の今日」と同じ月日に記録されたスポットをマップ画面上部にカード表示。該当が無い日は何も表示しない |
| タグ・カテゴリ付け | グルメ/絶景/記念日/ホテル/観光地のプリセットタグ+自由入力タグを記録に付与。記録作成画面で複数選択、スポット詳細・記録一覧・旅行タイムラインに表示 |

### Phase 3: 旅の計画機能 — **実装完了**

| 機能 | 内容 |
|---|---|
| ウィッシュリスト | 「次はここに行きたい」場所を、訪問済み(TRIP/SPOT)とは別の`wishes`コレクションで管理。地図上には点線アウトラインのピンで表示し、訪問済みのゴールド塗りつぶしピンと区別する。実際に訪れた後は、記録を作成した上でウィッシュリスト項目を手動で削除する(自動変換はしない) |
| 検索・絞り込み | 記録一覧画面で、日付範囲・国/都道府県・タグ(複数選択、いずれか一致)によるAND条件の絞り込み。絞り込み条件はURLのクエリパラメータに保持し、詳細画面へ遷移して戻っても維持される |
| 簡易費用記録 | 旅行単位で、おおまかな合計金額(円)のみを任意入力(内訳管理はしない)。旅行詳細画面で入力・修正、統計画面に全旅行の合計を表示 |

## 3. 非機能要件

| 項目 | 内容 |
|---|---|
| 対応環境 | iOS Safari(PWAとしてホーム画面に追加して利用)を主対象とするモダンブラウザ |
| 想定同時利用ユーザー数 | 2名固定 |
| データ保存先 | Firebase(Firestore / Storage) |
| ネットワーク要件 | 記録の閲覧はオフライン対応(Firestoreの永続ローカルキャッシュ+Service Workerによる写真キャッシュ)、同期はオンライン時に実施。書き込みはオフライン中もローカルには即時反映され、電波復帰後に自動同期される(保存直後にサーバーへの同期完了を確認できない場合は「同期待ち」である旨をUIで案内する) |
| セキュリティ | Firebase Authenticationによる二人限定のアクセス制御 + Phase2のプライバシーロック(WebAuthn/PIN) |
| 開発体制 | 個人開発(Claude Codeを利用した学習目的の開発) |

## 4. 技術スタック

| レイヤ | 採用技術 |
|---|---|
| UI | React 19 + Vite + TypeScript |
| ルーティング | react-router-dom v7(データルーター/`createBrowserRouter`。記録作成画面の離脱確認に`useBlocker`を利用するため) |
| アイコン | lucide-react(線画スタイルで統一) |
| データ永続化・共有 | Firebase Firestore(無料枠)。永続ローカルキャッシュを有効化し、オフライン閲覧・オフライン書き込みに対応 |
| 認証 | Firebase Authentication(無料枠、メール/パスワード方式) |
| 地図表示 | Leaflet + react-leaflet + GeoJSON(国・都道府県ポリゴンデータによる色分け表示)。タイルはCartoDB Voyager(明るい配色・英語表記)を使用し、この地図コンポーネントのみアプリ全体のダーク基調の例外として扱う |
| 地名検索 | OpenStreetMap Nominatim API(記録作成画面・ウィッシュリスト追加画面での場所検索。利用規約に従いデバウンス・レート制限を実装) |
| 位置情報取得 | ブラウザの Geolocation API |
| 画像保存 | Firebase Storage(Blazeプラン、無料枠内での運用+予算アラート設定) |
| 画像圧縮・サムネイル生成 | ブラウザ内(Canvas API)でアップロード時にフルサイズ(長辺1600px)と一覧表示用サムネイル(長辺300px)の2種類を生成し、両方をStorageに保存 |
| 画像撮影・選択 | ブラウザの File input(`capture`属性) |
| オフライン対応 | Firestore永続ローカルキャッシュ(データ)+ Service Worker/Workbox(アプリ本体・写真のキャッシュ) |
| ホーム画面追加 | Web App Manifest(vite-plugin-pwa) |
| 生体認証・ロック | WebAuthn(プラットフォーム認証器)+ 4桁PIN(ソルト付きハッシュで保存) |
| OCR(Phase4、未着手) | Tesseract.js等のブラウザ内OCRライブラリ、または無料枠のあるクラウドOCR(採用技術は未定) |
| ホスティング | Firebase Hosting(無料枠) |
| デプロイ | 開発者のWindows端末から手動デプロイ(`npm run deploy:hosting`)。GitHub Actions等での自動化は未着手 |

> Firebaseの無料枠(Sparkプラン)には読み書き回数・ストレージ容量に上限がありますが、二人だけの利用規模であれば通常は無料枠内に収まります。Storageのみ、リージョン制約によりBlazeプランへの登録が必要です(詳細はCLAUDE.md参照)。主要画面が同じFirestoreコレクションを短時間に複数回全件取得してしまう設計上の課題があり、応急処置として短時間キャッシュ(`src/lib/queryCache.ts`)を導入しているが、根本対応(購読への切り替え・クエリ設計の見直し)は今後の課題として残っている。
