# 要件定義書 v5

## プロジェクト名
COTABI - カップル旅行記録アプリ

## 1. プロジェクト概要

### 1.1 目的
- Claude Codeの実践練習として、実際のシステム開発プロジェクトの流れ(要件定義 → 仕様策定 → 実装)を体験する
- 副次的な成果物として、恋人と二人だけで使う旅行記録アプリを完成させる

### 1.2 対象ユーザー
- 本人および彼女の2名のみ(クローズドな利用、外部公開なし)

### 1.3 コンセプト
- 旅先で実用的に使えるツールでありつつ、これまでの旅の記録が視覚的に蓄積されていくアプリ
- 世界地図・日本地図上で訪問済みの国/都道府県が色付けされ、タップするとその場所での思い出(記録)を閲覧できる
- ホーム画面はマップをメインとし、「国をタップ→詳細記録を閲覧」という導線を軸にする

### 1.4 コスト方針
- 採用する技術・サービスは**すべて完全永続無料**であること(Claude Codeの利用料金は対象外)
- Apple Developer Program($99/年)への登録が前提となる機能・配布方式は採用しない

### 1.5 アプリ形態・配布方式(v5で変更)
- **ネイティブiOSアプリ(SwiftUI/Xcode)ではなく、PWA(Progressive Web App)として開発する**
- 変更理由: 無料のApple Developer Personal Teamでは、証明書・端末登録・インストール用プロファイルが**発行から7日で期限切れ**になる制約があり、Macなし・完全無料での長期運用が事実上困難と判明したため
- PWAであればMac・Xcode・Apple Developer Programが一切不要で、Windows上のブラウザ・エディタだけで開発が完結する
- ホーム画面へのアイコン追加、オフライン表示、位置情報・カメラアクセスなど、今回必要な機能の大部分はPWAで実現可能
- 制約: プッシュ通知やバックグラウンド処理の自由度はネイティブアプリより低い(iOS Safariの制限による)

### 1.6 開発環境
- 開発端末はWindows(Mac不要)。コーディングはWindows上のClaude Code / VS Codeで行う
- Macが一切不要なため、ビルド・デプロイもWindows上、または軽量なCI(GitHub Actions Ubuntuランナー)で完結する
- リポジトリは公開(public)のまま(CI無料枠確保、実データはリポジトリに含めない方針は変更なし)

## 2. 機能要件(全機能・フェーズ別)

### Phase 1: コア体験(MVP)

| 機能 | 内容 |
|---|---|
| 訪問マップ | 世界地図・日本地図で訪問済みの国/都道府県を色分け表示。タップで詳細記録へ遷移 |
| 旅行記録 | スポット単位(位置情報付き)で写真・日記・日付を記録。写真は1スポットにつき複数枚自由に追加可能 |
| 記録タイミング | 現地でのリアルタイム記録、帰宅後の清書きの両方に対応 |
| 記録者の区別 | 誰が記録したデータかを表示 |
| データ共有 | Firebase(Firestore + Authentication、無料枠)による二人限定の共有。片方の記録がもう一方にも同期 |
| 統計表示 | 訪問した国・都道府県の数を表示 |
| アルバムまとめ | 旅行単位(1回の旅行=1アルバム)で写真をまとめて閲覧 |
| 旅程表(レベル1) | スポットに日付・時刻を入力し、時系列のタイムラインとして表示 |
| ルート表示(レベル2) | 登録スポットの位置情報を時系列順に直線で結び、地図上に表示(実際の交通経路ではなく直線接続) |
| PWA基本機能 | ホーム画面へのアイコン追加、オフラインでの記録閲覧に対応(Service Worker) |

### Phase 2: 体験向上

| 機能 | 内容 |
|---|---|
| プライバシーロック | アプリ起動時に簡易ロック(PINまたはWebAuthnによる生体認証) |
| 思い出フラッシュバック | 「〇年前の今日」の記録を振り返り表示 |
| タグ・カテゴリ付け | グルメ/絶景/記念日などのタグを記録に付与し、後から探しやすくする |

### Phase 3: 旅の計画機能

| 機能 | 内容 |
|---|---|
| ウィッシュリスト | 「次はここに行きたい」場所を地図にピンできる、訪問済みとは別のリスト |
| 検索・絞り込み | 日付・場所・タグで記録を検索 |
| 簡易費用記録 | 旅行単位でのおおまかな費用を記録(家計簿ほど厳密ではない) |

### Phase 4: 拡張機能

| 機能 | 内容 |
|---|---|
| 動画対応 | 写真だけでなく動画も記録として追加可能に |
| コメント・リアクション | 二人の記録に対してコメントやリアクションを付けられる |
| チケット自動読み取り(OCR) | 予約チケット等の写真から日付・場所を自動抽出し、旅程表を自動生成 |
| プッシュ通知 | iOS SafariのWeb Push(iOS16.4以降)を用いた通知(制約あり) |

## 3. 非機能要件

| 項目 | 内容 |
|---|---|
| 対応環境 | iOS Safari(PWAとしてホーム画面に追加して利用)を主対象とするモダンブラウザ |
| 想定同時利用ユーザー数 | 2名固定 |
| データ保存先 | Firebase(Firestore / Storage) |
| ネットワーク要件 | 記録の閲覧はオフライン対応(Service Workerによるキャッシュ)、同期はオンライン時に実施 |
| セキュリティ | Firebase Authenticationによる二人限定のアクセス制御 + Phase2で簡易ロックを追加 |
| 開発体制 | 個人開発(Claude Codeを利用した学習目的の開発) |

## 4. 技術スタック(v5で全面変更)

| レイヤ | 採用技術 |
|---|---|
| UI | React + Vite |
| データ永続化・共有 | Firebase Firestore(無料枠) |
| 認証 | Firebase Authentication(無料枠) |
| 地図表示 | Leaflet + GeoJSON(国・都道府県ポリゴンデータによる色分け表示) |
| 位置情報取得 | ブラウザの Geolocation API |
| 画像保存 | Firebase Storage(Blazeプラン、無料枠内での運用+予算アラート設定) |
| 画像撮影・選択 | ブラウザの File input / getUserMedia API |
| オフライン対応 | Service Worker + Cache API |
| ホーム画面追加 | Web App Manifest(manifest.json) |
| 生体認証・ロック(Phase2) | WebAuthn、または簡易PINコード |
| OCR(Phase4) | Tesseract.js等のブラウザ内OCRライブラリ、または無料枠のあるクラウドOCR |
| ホスティング | Firebase Hosting(無料枠) |

> Firebaseの無料枠(Sparkプラン)には読み書き回数・ストレージ容量に上限がありますが、二人だけの利用規模であれば通常は無料枠内に収まります。Storageのみ、リージョン制約によりBlazeプランへの登録が必要です(詳細はCLAUDE.md参照)。

## 5. 開発の進め方(Claude Code活用方針)

1. **要件定義**(本ドキュメント) ← 今ここ
2. **画面設計・仕様書作成**(画面一覧、画面遷移図、データモデル設計)※Phase1範囲を優先、v3からの変更は技術用語のみ
3. **プロジェクト初期構築**(GitHubリポジトリ作成、React+Viteプロジェクトの雛形作成、CLAUDE.mdでプロジェクトルールを定義)← 完了
4. **Phase1の実装**(Windows上のClaude Codeにタスクを切って依頼 → ローカルのブラウザで確認 → 修正のサイクル)
5. **Firebase Hostingへのデプロイ・実機(iPhone)確認・Phase1の完成**
6. **Phase2以降を順次同様のサイクルで実装**
