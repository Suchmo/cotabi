# デザインシステム(COTABI)

アプリ全体の見た目を統一するためのガイドラインです。スマホ専用アプリという前提で、常にこのトーンで実装します。

## 1. コンセプト

「シック・都会的・夜の街並み」。派手さや可愛らしさではなく、落ち着いた大人っぽい雰囲気を基調とする。アイコン(ダークネイビー×ゴールド、二人の輪+街並み)の世界観をアプリ全体に広げる。

## 2. カラーパレット

| 用途 | カラーコード | 説明 |
|---|---|---|
| 背景(ベース) | `#11141a` | アプリ全体の背景色(ほぼ黒に近いダークネイビー) |
| 背景(カード等) | `#171b23` | カード・入力欄などの背景 |
| 背景(区切り・薄い面) | `#1b2029` | トグルの背景など |
| ボーダー・区切り線 | `#232833` | 下タブの上線など、控えめな境界線 |
| プレースホルダー面 | `#2a3038` | 画像プレースホルダーなど |
| テキスト(主) | `#f3f0e8` | 見出し・本文の主テキスト(オフホワイト) |
| テキスト(副・非選択) | `#7a8290` | 補足情報、非選択タブ |
| テキスト(さらに薄い) | `#4b515c` / `#5c6270` | 矢印アイコン、非選択アイコン等 |
| アクセント(ゴールド) | `#c4a45c` | 選択状態、ボタン、訪問済みマップの色分け、ロゴのアクセント |
| アクセント文字(ゴールド背景上) | `#241d0f` | ゴールド背景の上に乗せる濃い文字色 |
| 危険色(意味色の例外) | `#f87171` | 削除ボタン・エラーメッセージ専用。基本パレットには含めないが実用上の最小限の例外(詳細は6.) |

**方針**: 色数を増やさない。ゴールドは「アクセント・選択中・訪問済み」を示す1色に絞り、多用しすぎない。旅行ルートの色分け(複数旅行の識別用パレット)は例外的に複数色を使うが、ブランドカラーとは別枠として扱う。すべての色の値は`src/styles/theme.css`のCSSカスタムプロパティにまとめて定義しており、他のCSSからは直接の16進値ではなく`var(--color-*)`経由で参照する。

## 3. タイポグラフィ

- 見出し:14〜16px、font-weight 500
- 本文・補足:12〜13px、font-weight 400
- 数字を強調する箇所(統計画面など)は少し大きめ(20px前後)にしてよい

## 4. コンポーネントの方針

### カード
- 角丸:12px前後
- 背景:`#171b23`
- 余白:内側12〜16px、詰め込みすぎない
- 影(shadow)は使わない。フラットな面の重なりで表現する

### ボタン・トグル
- 選択中:ゴールド背景 + 濃い文字色(`#241d0f`)
- 非選択:透明または薄い背景 + `#7a8290`のテキスト
- 角丸は「pill(完全な丸み)」で統一(世界/日本トグルなど)

### 下タブ(BottomTabBar)
- 選択中のアイコン・文字はゴールド、非選択はグレー(`#5c6270`)
- アイコンは線画(アウトライン)スタイルで統一
- 上部に1pxの区切り線(`#232833`)

### アイコン
- 線画(アウトライン)スタイルのアイコンセットで統一する(塗りつぶしアイコンは使わない)
- 太さ・サイズ感を画面内で揃える

## 5. マップの配色・タイル

- 訪問済み:ゴールド(`#c4a45c`)塗りつぶし
- 未訪問:グレー(`#2a3038`程度の落ち着いた面)
- ウィッシュリスト(行きたい場所):訪問済みと明確に区別するため、塗りつぶさない点線アウトラインの丸ピン(ゴールドの輪郭のみ)
- 派手な多色使いをしない。「訪問済みかどうか」が一目でわかることを優先する
- 複数旅行のルート色分け(識別用パレット)は例外的に複数色を使うが、ブランドカラーとは別枠として扱う(旅行の作成順に固定パレットを自動割り当て)

### タイルの扱い(デザインシステムの唯一の例外)
- 地図タイル自体(GeoMap・RouteMap・WishlistMapが表示する背景地図)は、**このデザインシステムのダーク基調の対象外**とする
- 実際の地形が判読しやすいよう、明るい配色(海=青系・陸=緑系)・英語表記のCartoDB Voyagerタイルを使用する
- タブ・カード・ボタンなど地図以外のUIはすべて本デザインシステムのダーク基調のまま。「地図の中だけ明るい」状態が意図した見た目である

### マーカーアイコン
- 訪問済みスポットの単発マーカー:ゴールド基調のカスタムピン画像(影なし、フラット)
- ウィッシュリストのマーカー:CSSで描画する点線アウトラインの丸(画像アセットは使わない)

## 6. コンポーネント補足

### 確認ダイアログ(ConfirmDialog)
- 削除など取り消せない操作の前は、ブラウザ標準の`window.confirm()`ではなく、本デザインシステムのトーンに合わせた独自モーダル(`ConfirmDialog`)を必ず使う
- 背景は半透明の黒でオーバーレイし、ダイアログ本体はカードと同じ`#171b23`・角丸12px
- 「削除する」ボタンは危険色(`#f87171`、後述)のアウトラインで強調し、ゴールドの通常ボタンとは明確に区別する

### フォームの入力チェック表示
- 必須項目の未入力チェックは、ブラウザ標準の吹き出し(見た目がテーマと合わない)に頼らない。`<form noValidate>`とし、独自のエラーメッセージ(下記の危険色テキスト)で表示する

### 危険色(意味色の例外)
- `#f87171`(`--color-danger`)を、削除ボタン・エラーメッセージ専用の意味色として使う。デザインシステムの基本パレット(ゴールド1色に絞る方針)には含めないが、実用上必要な最小限の例外として扱う

## 7. タップ領域の方針

- インタラクティブな要素(ボタン・リンク)は、原則として**最小44px四方**のタップ領域を確保する
- 例外として、以下のような「周囲のレイアウトを崩さずには44px化できない、二次的・低頻度の操作」に限り、44px未満のタップ領域を許容する
  - 画面幅に応じて折り返す小さなチップの集合(タグ選択など)。44px化すると多数ある場合に縦方向へ大きく間延びしてしまうもの
  - 84px角程度の小さなサムネイル画像の隅に重ねて表示する削除バッジ。44px化すると隣接するサムネイルと重なってしまうもの
- 上記いずれにも当てはまらない場合は、44pxで実装する

## 8. やらないこと

- グラデーション、ドロップシャドウ、ネオン調の光彩効果は使わない(地図タイル自体を除く。タイルは5.の例外として明るい配色を使う)
- 絵文字は使わない(アイコンフォント等の線画アイコンで統一)
- ポップで賑やかな配色(原色の多用)は避ける
