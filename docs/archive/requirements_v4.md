# 要件定義書 v4

## プロジェクト名(仮)
Wander Log(仮称) - カップル旅行記録アプリ

## 1. プロジェクト概要

### 1.1 目的
- Claude Codeの実践練習として、実際のシステム開発プロジェクトの流れ(要件定義 → 仕様策定 → 実装)を体験する
- 副次的な成果物として、恋人と二人だけで使う旅行記録アプリを完成させる

### 1.2 対象ユーザー
- 本人および彼女の2名のみ(クローズドな利用、外部公開なし)

### 1.3 コンセプト
- 旅先で実用的に使えるツールでありつつ、これまでの旅の記録が視覚的に蓄積されていくアプリ
- 世界地図・日本地図上で訪問済みの国/都道府県が色付けされ、タップするとその場所での思い出(記録)を閲覧できる
- ホーム画面はマップをメインとし、「国をタップ→詳細記録を閲覧」という導線を軸にする

### 1.4 コスト方針
- 採用する技術・サービスは**すべて完全永続無料**であること(Claude Codeの利用料金は対象外)
- Apple Developer Program($99/年)への登録が前提となる機能(CloudKit、WeatherKit、MusicKit等)は採用しない
- アプリの配布はApp Storeを介さず、個人のiPhone2台に直接ビルド・インストールする(無料のPersonal Teamで対応可能)

### 1.5 開発・ビルド環境
- 開発端末はWindows(Mac購入なし)。コーディングはWindows上のClaude Code / VS Codeで行う
- iOSアプリのビルド・署名にはmacOS環境が必須のため、GitHub Actionsのクラウドmacランナーを利用する
- GitHub Actionsのビルド無料枠を十分に確保するため、リポジトリは公開(public)とする
  - 実データ(写真・日記等)はFirebase側に保存され、リポジトリには含まれない
  - Firebaseの認証情報等はGitHub Secretsで管理し、コード上には含めない

## 2. 機能要件(全機能・フェーズ別)

### Phase 1: コア体験(MVP)

| 機能 | 内容 |
|---|---|
| 訪問マップ | 世界地図・日本地図で訪問済みの国/都道府県を色分け表示。タップで詳細記録へ遷移 |
| 旅行記録 | スポット単位(位置情報付き)で写真・日記・日付を記録。写真は1スポットにつき複数枚自由に追加可能 |
| 記録タイミング | 現地でのリアルタイム記録、帰宅後の清書きの両方に対応 |
| 記録者の区別 | 誰が記録したデータかを表示 |
| データ共有 | Firebase(Firestore + Authentication、無料枠)による二人限定の共有。片方の記録がもう一方にも同期 |
| 統計表示 | 訪問した国・都道府県の数を表示 |
| アルバムまとめ | 旅行単位(1回の旅行=1アルバム)で写真をまとめて閲覧 |
| 旅程表(レベル1) | スポットに日付・時刻を入力し、時系列のタイムラインとして表示 |
| ルート表示(レベル2) | 登録スポットの位置情報を時系列順に直線で結び、地図上に表示(実際の交通経路ではなく直線接続) |

### Phase 2: 体験向上

| 機能 | 内容 |
|---|---|
| プライバシーロック | Face ID/Touch IDでアプリ起動時にロック |
| 思い出フラッシュバック | 「〇年前の今日」の記録を振り返り表示 |
| タグ・カテゴリ付け | グルメ/絶景/記念日などのタグを記録に付与し、後から探しやすくする |

### Phase 3: 旅の計画機能

| 機能 | 内容 |
|---|---|
| ウィッシュリスト | 「次はここに行きたい」場所を地図にピンできる、訪問済みとは別のリスト |
| 検索・絞り込み | 日付・場所・タグで記録を検索 |
| 簡易費用記録 | 旅行単位でのおおまかな費用を記録(家計簿ほど厳密ではない) |

### Phase 4: 拡張機能

| 機能 | 内容 |
|---|---|
| 天気情報の自動記録 | 記録した日・場所の天気を自動取得して残す |
| 動画対応 | 写真だけでなく動画も記録として追加可能に |
| コメント・リアクション | 二人の記録に対してコメントやリアクションを付けられる |
| チケット自動読み取り(OCR) | 予約チケット等の写真/PDFから日付・場所を自動抽出し、旅程表を自動生成 |

## 4. 技術スタック(案)

| レイヤ | 採用技術 |
|---|---|
| UI | SwiftUI |
| データ永続化・共有 | Firebase Firestore(無料枠) |
| 認証 | Firebase Authentication(無料枠) |
| 地図表示 | MapKit または SVGベースの独自マップコンポーネント(国・県ごとの色分け用) |
| 位置情報取得 | Core Location(無料) |
| 画像保存 | Firebase Storage(無料枠、または将来的に枠を超えた場合は圧縮運用で対応) |
| 生体認証(Phase2) | LocalAuthentication フレームワーク(無料) |
| 天気情報取得(Phase4) | Open-Meteo等の無料天気API(APIキー不要・完全無料) |
| OCR(Phase4) | Vision フレームワーク(無料・オンデバイス処理) |

> 世界地図/日本地図の「国・都道府県ごとに色分け」という要件は、MapKitの標準機能だけでは実現しづらいため、地域ごとのポリゴンデータ(GeoJSON等)を用いた独自描画が必要になる見込みです。この点は仕様設計フェーズで詳細化します。
>
> Firebaseの無料枠(Sparkプラン)には読み書き回数・ストレージ容量に上限がありますが、二人だけの利用規模であれば通常は無料枠内に収まります。念のため利用量の監視は仕様設計フェーズで検討します。

## 5. 開発の進め方(Claude Code活用方針)

1. **要件定義**(本ドキュメント) ← 今ここ
2. **画面設計・仕様書作成**(画面一覧、画面遷移図、データモデル設計)※Phase1範囲を優先
3. **プロジェクト初期構築**(GitHubリポジトリ作成、GitHub Actionsでのビルド・署名パイプライン構築、CLAUDE.mdでプロジェクトルールを定義)
4. **Phase1の実装**(Windows上のClaude Codeにタスクを切って依頼 → クラウドビルドで実機確認 → 修正のサイクル)
5. **実機確認・Phase1の完成**
6. **Phase2以降を順次同様のサイクルで実装**
